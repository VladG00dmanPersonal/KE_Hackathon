# Подробное руководство по работе с проектом

Этот файл нужен для простой задачи: открыть репозиторий и быстро понять, что здесь происходит, где что лежит, что можно сделать через интерфейс, а что меняется через код.

Если совсем коротко: это серверное Flask-приложение на Python с HTML-шаблонами Jinja, одной SQLite-базой, общим CSS-файлом, несколькими маленькими JS-файлами и загрузкой пользовательских файлов в `app/static/uploads`.

## 1. Что это за проект

Проект уже не выглядит как "пустой шаблон". В нём есть:

- главная страница;
- регистрация и вход;
- профиль;
- роли пользователей;
- каталог товаров;
- карточка товара;
- отзывы и оценки;
- корзина и оформление заказа с баланса;
- пользовательские товары;
- админ-панель;
- календарь;
- редактируемая таблица;
- статистика с Matplotlib;
- пример формы с загрузкой файлов;
- личный чат;
- раздел "Реклама" как отдельная страница-заглушка.

Главная мысль по архитектуре такая:

1. Python/Flask принимает запрос.
2. Route в `app/routes/*.py` читает или меняет данные.
3. SQLite хранит данные в `instance/hackathon.sqlite`.
4. Jinja-шаблон в `app/templates` рисует HTML.
5. CSS и JS из `app/static` улучшают внешний вид и поведение.

## 2. Быстрый старт

### Что нужно установить

- Python 3.12 или совместимую версию.
- `pip`.

### Команды запуска на Windows PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\activate
pip install -r requirements.txt
python -m flask --app run.py init-db
python -m flask --app run.py run
```

После этого сайт открывается по адресу:

```text
http://127.0.0.1:5000
```

### Очень важный момент про `init-db`

Команда:

```powershell
python -m flask --app run.py init-db
```

полностью пересоздаёт таблицы по `app/schema.sql` и заново заливает демо-данные из `app/db.py`.

Это значит:

- старые данные будут потеряны;
- заказы, товары, события, заявки, сообщения и формы сотрутся;
- команду безопасно использовать только когда вы точно хотите полный сброс.

### Демо-аккаунты после `init-db`

- `admin@example.com` / `admin123`
- `user@example.com` / `user123`

### Если Flask "не найден"

Если команда запуска падает с чем-то вроде `No module named flask`, значит зависимости не установились в текущее окружение. Тогда снова выполните:

```powershell
pip install -r requirements.txt
```

### Как узнать все маршруты

Очень полезная команда:

```powershell
python -m flask --app run.py routes
```

Она показывает все URL проекта и помогает понять, жив ли нужный route.

## 3. Где реально лежат данные и файлы

### База данных

Рабочая база по текущей конфигурации лежит здесь:

```text
instance/hackathon.sqlite
```

Это настраивается в `app/__init__.py` через `app.config["DATABASE"]`.

Важно:

- файл `instance/app.sqlite` сейчас не используется приложением;
- если вы меняете "не ту" базу, на сайте ничего не изменится.

### Загруженные файлы

Пользовательские файлы сохраняются сюда:

```text
app/static/uploads/
```

Внутри есть подпапки:

- `app/static/uploads/products` — картинки товаров;
- `app/static/uploads/topups` — чеки пополнения;
- `app/static/uploads/forms` — файлы и картинки из примера формы.

### Что можно бэкапить перед опасными изменениями

Если боитесь потерять данные, перед изменениями БД просто скопируйте файл:

```powershell
Copy-Item instance\hackathon.sqlite instance\hackathon.backup.sqlite
```

## 4. Карта проекта

### Корень репозитория

```text
run.py
requirements.txt
README.md
PROJECT_GUIDE.md
app/
instance/
```

### Что лежит в `app/`

```text
app/
  __init__.py            # создание Flask-приложения, config, blueprints
  db.py                  # подключение к SQLite, init-db, сиды
  schema.sql             # полная схема БД
  product_service.py     # вспомогательная логика товаров и загрузки картинок
  utils.py               # декораторы доступа, filename, валидации
  routes/                # все Flask blueprints
  templates/             # Jinja HTML
  static/css/styles.css  # основной CSS
  static/js/             # клиентская логика
  static/uploads/        # пользовательские загрузки
```

### Что лежит в `instance/`

- `hackathon.sqlite` — рабочая БД;
- `server.stdout.log` и `server.stderr.log` — служебные логи;
- `app.sqlite` — лишний пустой файл, который приложением не используется.

## 5. Как понять, куда лезть при любой правке

Это самая полезная ментальная модель для проекта.

Если вы хотите:

- поменять текст, кнопки, HTML-блоки — смотрите `app/templates`;
- поменять серверную логику — смотрите `app/routes`;
- поменять сохранение данных — смотрите `app/routes`, `app/product_service.py`, `app/db.py`, `app/schema.sql`;
- поменять стили — смотрите `app/static/css/styles.css`;
- поменять поведение в браузере — смотрите `app/static/js`;
- добавить новый раздел — почти всегда правятся и route, и template, и иногда БД.

Проще всего думать так:

1. "Что увидит пользователь?"
2. "Кто это отрисует?"
3. "Откуда возьмутся данные?"
4. "Куда они сохранятся?"

## 6. Роли и права

В проекте есть роли:

- `user`
- `manager`
- `admin`

По факту на текущий момент:

- `user` — обычный пользователь;
- `admin` — доступ к админке и управлению товарами/заявками/ролями;
- `manager` — роль хранится в БД и выпадающем списке админки, но отдельной логики доступа под неё в коде сейчас нет.

Это важно: если вы выставите пользователю роль `manager`, он не получит никаких особых экранов автоматически, пока вы сами не добавите проверки через `roles_required(...)`.

## 8. Как пользоваться сайтом как обычный человек

### 8.1 Главная страница

Что делает:

- показывает витрину проекта;
- выводит счётчики;
- показывает последние товары;
- даёт быстрые ссылки в основные модули.

Где менять:

- логика: `app/routes/main.py`;
- вёрстка: `app/templates/index.html`.

### 8.2 Регистрация и вход

Что делает:

- создаёт пользователя;
- проверяет email, никнейм и пароль;
- логинит через `session["user_id"]`.

Правила:

- email должен содержать `@`;
- никнейм валидируется в `app/utils.py`;
- пароль минимум 6 символов.

Где менять:

- логика: `app/routes/auth.py`;
- шаблоны: `app/templates/auth/register.html`, `app/templates/auth/login.html`.

### 8.3 Каталог товаров

Что умеет:

- поиск по названию;
- фильтрация по нескольким категориям;
- фильтрация по одному тегу;
- фильтрация по цене;
- сортировка;
- переключение вида "карточки/список";
- быстрый переход на карточку товара;
- добавление товара в корзину;
- добавление товара через модальное окно, если пользователь вошёл.

Где менять:

- логика списка: `app/routes/products.py`, функция `index()`;
- шаблон списка: `app/templates/products/index.html`;
- карточка элемента: `app/templates/components/product_card.html`;
- JS фильтров: `app/static/js/catalog-filters.js`.

### 8.4 Как добавить товар через интерфейс

1. Войти в аккаунт.
2. Открыть каталог или "Мои товары".
3. Нажать кнопку "Добавить товар".
4. Заполнить:
   - название;
   - описание;
   - категорию или новую категорию;
   - цену;
   - остаток;
   - теги;
   - новые теги;
   - картинку.
5. Сохранить.

Что происходит внутри:

- данные собираются в `product_payload()` из `app/product_service.py`;
- валидируются в `validate_product(...)`;
- картинка сохраняется через `save_product_image(...)`;
- новая категория и новые теги при необходимости создаются автоматически.

### 8.5 Как изменить или удалить свой товар

Из интерфейса:

1. Открыть выпадающее меню профиля.
2. Перейти в "Мои товары".
3. Нажать "Изменить" или "Удалить".

Права:

- обычный пользователь может менять только свои товары;
- админ может менять любые товары.

Важно:

- пользователь видит только свои товары;
- переключатель `is_active` доступен только админу;
- удаление удаляет запись товара из таблицы `products`.

### 8.6 Карточка товара

- картинка;

- теги;

## 9. Как добавлять, убирать и менять разделы

### 9.1 Как добавить новую страницу

Минимальный рецепт:

1. Создать новый файл в `app/routes`, например `about.py`.
2. Описать `Blueprint`.
3. Сделать route.
4. Зарегистрировать blueprint в `app/__init__.py`.
5. Создать шаблон в `app/templates`.
6. При необходимости добавить ссылку в `app/templates/base.html`.
7. Если надо, добавить стили и JS.

Пример:

```python
from flask import Blueprint, render_template

bp = Blueprint("about", __name__, url_prefix="/about")


@bp.route("/")
def index():
    return render_template("about.html")
```

Что не забыть:

- имя blueprint должно быть уникальным;
- в `base.html` ссылка почти всегда делается через `url_for("about.index")`;
- если страница должна быть только для авторизованных, повесьте `@login_required`;
- если нужен доступ только админу, используйте `@roles_required("admin")`.

### 9.2 Как убрать страницу

Делайте в таком порядке:

1. Найдите все ссылки на страницу:
   ```powershell
   rg -n "about" app
   ```
2. Удалите пункт меню из `app/templates/base.html`.
3. Удалите регистрацию blueprint из `app/__init__.py`.
4. Удалите route-файл или ненужные функции из него.
5. Удалите шаблон.
6. Удалите связанные JS/CSS, если они больше нигде не используются.
7. Если страница имела свою таблицу в БД, отдельно решите, нужно ли убирать и данные.

Не делайте удаление "наполовину". Если оставить `url_for(...)` на несуществующий endpoint, приложение упадёт при рендере страницы.

### 9.3 Как добавить пункт меню

Меню лежит в:

```text
app/templates/base.html
```

Что менять:

- верхняя навигация;
- выпадающее меню профиля;
- иногда footer-навигация.

### 9.4 Как убрать пункт меню

1. Удалите ссылку из `base.html`.
2. Проверьте, не осталась ли такая же ссылка в footer.
3. Проверьте, не ссылается ли на раздел главная страница `index.html`.

### 9.5 Как добавить кнопку с модальным окном

В проекте уже есть общая логика модалок в `app/static/js/modals.js`.

Чтобы кнопка открывала диалог:

```html
<button type="button" data-open-dialog="my-dialog">Открыть</button>

<dialog class="app-modal" id="my-dialog">
    <div class="modal-head">
        <strong>Заголовок</strong>
        <button class="ghost" type="button" data-close-dialog>Закрыть</button>
    </div>
    ...
</dialog>
```

### 9.6 Как добавить подтверждение перед отправкой формы

`modals.js` уже умеет перехватывать форму, если у неё есть нужные `data-*`.

Пример:

```html
<form
    method="post"
    data-confirm-title="Удалить запись?"
    data-confirm-message="Запись будет удалена без возможности восстановления."
    data-confirm-confirm-label="Удалить"
    data-confirm-variant="danger"
>
    <button type="submit">Удалить</button>
</form>
```

Варианты:

- `data-confirm-variant="danger"` — красный опасный сценарий;
- без `variant` — обычное нейтральное подтверждение.

### 9.7 Как добавить кнопку предпросмотра изображения

Уже готово в `app/static/js/image-preview.js`.

Пример:

```html
<button
    type="button"
    data-preview-src="{{ url_for('static', filename=item.image_path) }}"
    data-preview-title="Предпросмотр"
>
    Открыть
</button>
```

### 9.8 Как добавить новый CSS

Основной файл:

```text
app/static/css/styles.css
```

Правило простое:

- если стиль общий, добавляйте его туда;
- если стиль относится только к одному экрану, всё равно лучше сгруппировать его под осмысленным префиксом класса, а не разбрасывать анонимные селекторы.

### 9.9 Как добавить новый JavaScript

1. Создайте файл в `app/static/js`.
2. Подключите его в шаблоне через блок `{% block scripts %}`.

Пример:

```html
{% block scripts %}
<script src="{{ url_for('static', filename='js/my-feature.js') }}"></script>
{% endblock %}
```

### 9.10 Как добавить новую форму

Почти всегда нужны 4 вещи:

1. HTML-форма в шаблоне.
2. Route с `GET` и/или `POST`.
3. Валидация полей.
4. Сохранение в БД.

Хороший пример в этом проекте:

- `app/routes/forms.py`
- `app/templates/forms/example.html`

### 9.11 Как добавить загрузку файла

В проекте уже есть готовые паттерны:

- `save_product_image(...)` в `app/product_service.py`;
- `save_upload(...)` в `app/routes/forms.py`;
- логика загрузки чека в `app/routes/profile.py`.

Общий порядок:

1. Проверить, что есть нужная папка в `UPLOAD_FOLDER`.
2. Проверить расширение через `allowed_file(...)`.
3. Сгенерировать безопасное имя через `unique_filename(...)`.
4. Сохранить файл в `app/static/uploads/...`.
5. Сохранить путь в БД.

### 9.12 Как добавить новую таблицу в БД

Если проект можно сбросить:

1. Добавьте таблицу в `app/schema.sql`.
2. При необходимости добавьте сиды в `seed_db(db)` внутри `app/db.py`.
3. Выполните:
   ```powershell
   python -m flask --app run.py init-db
   ```

Если данные терять нельзя:

1. Добавьте новую структуру в `app/schema.sql`.
2. Добавьте безопасную миграционную логику в `ensure_runtime_schema()` в `app/db.py`.
3. Используйте `CREATE TABLE IF NOT EXISTS`, `CREATE INDEX IF NOT EXISTS`, иногда `ALTER TABLE`.

### 9.13 Как добавить новый столбец в существующую таблицу

Порядок безопаснее такой:

1. Обновить `app/schema.sql`, чтобы новая установка создавала столбец сразу.
2. Добавить код в `ensure_runtime_schema()` для старых баз.
3. Обновить SQL-запросы, которые читают или пишут эту таблицу.
4. Обновить шаблоны и формы.

### 9.14 Как удалить таблицу или поле

Это уже опасная операция.

Перед удалением:

1. Сделайте backup `instance/hackathon.sqlite`.
2. Найдите все использования по проекту:
   ```powershell
   rg -n "table_name|column_name" app
   ```
3. Удалите обращения из route, template, JS и сервисов.
4. Только потом меняйте схему.

### 9.15 Как добавить новый модуль "под ключ"

Для любой новой сущности удобно идти по чек-листу:

1. Решить, нужна ли таблица в БД.
2. Добавить схему.
3. Добавить route-файл или route-функции.
4. Зарегистрировать blueprint.
5. Сделать шаблон списка.
6. Сделать шаблон формы или модалку.
7. Добавить ссылку в меню.
8. Добавить стили.
9. Добавить JS только если он действительно нужен.
10. Протестировать руками.

## 11. Что можно и нельзя убирать через интерфейс

Через интерфейс уже можно:

- добавить товар;
- изменить товар;
- удалить свой товар;
- админом удалить любой товар;
- добавить событие календаря;
- удалить событие календаря;
- добавить строку таблицы;
- изменить строку таблицы;
- удалить строку таблицы;
- отправить форму;
- отправить сообщение;
- отправить заявку на пополнение;
- изменить роль пользователя админом.

Через интерфейс сейчас нельзя:

- удалить пользователя;
- удалить категорию отдельно от товаров;
- удалить тег отдельно от товаров;
- вручную редактировать историю заказов;
- вручную редактировать статистические точки;
- управлять разделом "Реклама" через админку.

Если это нужно, придётся:

- либо править БД руками;
- либо делать отдельный экран/route под такую операцию.

## 12. Как искать, где что ломается

### Если не знаете, где лежит текст

Ищите так:

```powershell
rg -n "Точный текст кнопки или заголовка" app
```

### Если не знаете, где лежит route

Ищите по endpoint или URL:

```powershell
rg -n "products.index|/products/" app
```

### Если не знаете, откуда берётся форма

Ищите по `action`, `name=` или тексту кнопки.

Примеры:

```powershell
rg -n "name=\"nickname\"" app
rg -n "Сохранить никнейм" app
rg -n "url_for\\('profile.change_nickname'\\)" app
```

### Если страница открывается, но данные не сохраняются

Проверьте по порядку:

1. правильный ли `method`;
2. правильный ли `action`;
3. читает ли route нужные поля из `request.form`;
4. есть ли `db.commit()`;
5. в ту ли базу смотрит приложение;
6. нет ли валидации, которая тихо отбрасывает значение.

## 13. Уже готовые JS-привязки, которые важно не сломать

### `theme.js`

Ожидает кнопку:

```html
<button data-theme-toggle>...</button>
```

Меняет `document.documentElement.dataset.theme` и пишет тему в `localStorage`.

### `modals.js`

Ожидает:

- `data-open-dialog="dialog-id"`
- `data-close-dialog`
- формы с `data-confirm-message`

### `image-preview.js`

Ожидает кнопки:

- `data-preview-src`
- `data-preview-title`

### `stats.js`

Ожидает картинки с:

- `data-chart="statuses"`
- `data-chart="orders"`
- `data-chart="points"`

### `catalog-filters.js`

Ожидает структуру каталога:

- `.catalog-filter-form`
- `.check-chip`
- `[data-all-categories]`
- `input[name='view']`

Если сильно меняете HTML каталога, этот JS нужно менять вместе с шаблоном.

## 14. Что проверить после любых изменений

Минимальный ручной чек-лист:

1. Главная открывается.
2. Каталог открывается.
3. Нет ошибки в `base.html`.
4. Логин работает.
5. Нужная страница открывается по правильному URL.
6. Форма действительно сохраняет данные.
7. После отправки есть `flash` и редирект туда, куда ожидается.
8. Если добавляли поле в БД, оно читается и записывается.
9. Если добавляли файл, он попал в нужную папку.
10. Если добавляли кнопку удаления, подтверждение реально появляется.

## 15. Подводные камни именно этого репозитория

### `init-db` всё удаляет

Это не миграция, а пересоздание.

### `manager` пока почти декоративный

Роль есть, но специальных экранов или прав под неё в коде почти нет.

### В проекте есть неиспользуемый `instance/app.sqlite`

Не ориентируйтесь на него. Рабочая база — `instance/hackathon.sqlite`.

### Раздел "Реклама" устроен чуть криво

Текущий route рендерит `app/templates/advertisements.html`, а не `app/templates/advertisements/index.html`.

### Загрузки лежат внутри `static`

Это удобно для демо, но значит:

- файлы сразу доступны как static;
- при чистке папок можно случайно удалить пользовательские изображения.

## 16. Самый практичный способ "сделать что угодно"

Если вам дали задачу, а вы не знаете, с чего начать, идите в таком порядке:

1. Откройте нужную страницу в браузере.
2. Поймите, что именно надо изменить: текст, поведение, данные или внешний вид.
3. Найдите шаблон по тексту через `rg`.
4. Найдите route по `url_for(...)` или URL.
5. Найдите таблицу БД, если страница работает с данными.
6. Меняйте маленькими шагами.
7. После каждого шага запускайте страницу снова.

Для этого проекта это почти всегда самый быстрый путь.
