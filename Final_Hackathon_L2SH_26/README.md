# Hackathon Flask Template

Минималистичный шаблон для хакатона на обязательном стеке: Python, Flask, HTML, CSS, SQLite. Проект разделён на маршруты, шаблоны, компоненты, стили, JavaScript и загрузки файлов.

## Что внутри

- Авторизация по почте и паролю, уникальные никнеймы пользователей.
- Роли аккаунтов: `user`, `manager`, `admin`.
- Профиль, смена пароля через старый пароль, заявка на смену почты с отменой.
- Пополнение баланса через заявку с изображением оплаты и подтверждением админом.
- Каталог товаров с поиском, быстрым просмотром по категориям, кликабельными тегами, рейтингами, комментариями, страницей товара и CRUD.
- Пользователи могут добавлять, редактировать и удалять свои товары.
- Корзина, оформление заказа с баланса, уменьшение остатков.
- Календарь с событиями по дням.
- Редактируемая таблица: добавление, изменение, удаление строк.
- Страница статистики с динамичными Matplotlib-графиками и выгрузкой CSV.
- Пример формы с текстом, числами, ползунком, radio-пунктами, чекбоксами, картинкой и файлом.
- SQLite-база со схемой и 15 демо-товарами.
- Главная страница собрана на Bootstrap-блоках, общий layout дополнен flash-сообщениями, компонентами, footer и адаптивным CSS.

## Запуск

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m flask --app run.py init-db
python -m flask --app run.py run
```

После запуска откройте `http://127.0.0.1:5000`.

Демо-аккаунты:

- Админ: `admin@example.com` / `admin123`
- Пользователь: `user@example.com` / `user123`

```text

```

## Как создать новую страницу

В проекте страницы обычно состоят из трёх частей:

1. `route` в `app/routes/*.py`
2. HTML-шаблон в `app/templates`
3. При необходимости стили в `app/static/css/styles.css` и JS в `app/static/js`

Пример добавления страницы `about`:

1. Создайте новый файл `app/routes/about.py`:

```python
from flask import Blueprint, render_template

bp = Blueprint("about", __name__, url_prefix="/about")


@bp.route("/")
def index():
    return render_template("about.html")
```

2. Зарегистрируйте blueprint в `app/__init__.py`:

```python
from .routes import about

app.register_blueprint(about.bp)
```

3. Создайте шаблон `app/templates/about.html`:

```html
{% extends "base.html" %}
{% block title %}О проекте{% endblock %}
{% block content %}
<section class="section">
    <h1>О проекте</h1>
    <p>Новая страница работает через Flask route и Jinja-шаблон.</p>
</section>
{% endblock %}
```

4. Если нужна ссылка в меню, добавьте её в `app/templates/base.html`.
5. Если странице нужны свои стили, добавьте классы в `app/static/css/styles.css`.

Текущий паттерн проекта такой:

- в `app/routes` лежит серверная логика разделов;
- в `app/templates` лежит разметка;
- `base.html` задаёт общий layout;
- страница рендерится через `render_template(...)`.

## Как изменить базу данных

База данных в проекте построена на SQLite и описана в `app/schema.sql`.

Есть два основных сценария:

### 1. Новая база или полный сброс

Если можно пересоздать базу, измените `app/schema.sql`, затем выполните:

```bash
python -m flask --app run.py init-db
```

Команда:

- пересоздаст таблицы;
- применит схему из `schema.sql`;
- заполнит базу демо-данными из `app/db.py`.

Важно: `init-db` удаляет старые данные, потому что `schema.sql` начинается с `DROP TABLE IF EXISTS`.

### 2. Существующая база, которую нельзя потерять

Если база уже используется, простого `init-db` делать не стоит. Для таких случаев в проекте есть функция `ensure_runtime_schema()` в `app/db.py`: она позволяет аккуратно добавлять недостающие таблицы и индексы при старте приложения.

Рекомендуемый подход:

1. Добавьте новую структуру в `app/schema.sql`, чтобы новая установка проекта сразу создавала правильную схему.
2. Добавьте совместимое изменение в `app/db.py` внутри `ensure_runtime_schema()`, например `CREATE TABLE IF NOT EXISTS ...`.
3. Если меняете существующую таблицу, используйте SQL уровня `ALTER TABLE ...` или отдельную логику обновления в `ensure_runtime_schema()`.

Пример безопасного добавления новой таблицы:

```python
db.executescript(
    """
    CREATE TABLE IF NOT EXISTS notes (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        user_id INTEGER NOT NULL,
        body TEXT NOT NULL,
        created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
    );
    """
)
```

Если вы добавляете демо-данные для новой сущности, сделайте это в `seed_db(db)` внутри `app/db.py`.

## Как добавлять логику на страницу

В этом шаблоне логика страницы может жить на трёх уровнях.

### 1. Серверная логика Flask

Это основная логика страницы:

- чтение данных из БД;
- валидация форм;
- обработка `GET` и `POST`;
- `flash(...)` сообщения;
- рендер шаблона через `render_template(...)`;
- редиректы через `redirect(...)` и `url_for(...)`.

Пример типичного обработчика:

```python
@bp.route("/", methods=("GET", "POST"))
def index():
    if request.method == "POST":
        value = request.form.get("value", "").strip()
        # валидация и сохранение
        flash("Сохранено.", "success")
        return redirect(url_for("example.index"))

    rows = get_db().execute("SELECT * FROM table_name").fetchall()
    return render_template("example.html", rows=rows)
```

### 2. Логика внутри шаблона Jinja

Шаблон может:

- выводить данные из Flask;
- делать циклы `{% for %}`;
- использовать условия `{% if %}`;
- строить ссылки через `url_for(...)`;
- наследоваться от `base.html`.

Пример:

```html
{% for row in rows %}
    <article class="list-row">
        <strong>{{ row.name }}</strong>
    </article>
{% else %}
    <p class="empty">Данных пока нет.</p>
{% endfor %}
```

### 3. Клиентская логика JavaScript

Если нужна интерактивность без перезагрузки или визуальные эффекты, добавляйте JS в `app/static/js`. В проекте уже есть примеры:

- `theme.js` для переключения темы;
- `stats.js` для графиков;
- `modals.js` для модальных окон;
- `image-preview.js` для предпросмотра.

Подключать скрипты лучше через блок `{% block scripts %}` в шаблоне страницы.

## Как работает стек технологий

Проект использует простой и понятный стек для хакатона.

### Python

Python отвечает за всю серверную часть:

- запуск приложения;
- обработку HTTP-запросов;
- бизнес-логику;
- работу с файлами;
- работу с SQLite;
- подготовку данных для шаблонов.

### Flask

Flask — это веб-фреймворк, который связывает всё вместе.

Он даёт:

- маршруты (`@bp.route(...)`);
- blueprints для разбиения проекта по разделам;
- шаблонизацию через Jinja;
- `session`, `g`, `flash`, `redirect`, `url_for`;
- интеграцию с формами, куками и ответами сервера.

В этом проекте каждый раздел вынесен в свой blueprint: `auth`, `products`, `profile`, `chat`, `calendar` и так далее.

### Jinja2 + HTML

HTML-шаблоны лежат в `app/templates`. Flask передаёт в них данные, а Jinja подставляет значения, циклы и условия.

За счёт этого:

- один `base.html` задаёт общий каркас сайта;
- отдельные страницы переиспользуют layout;
- компоненты можно выносить в `app/templates/components`.

### CSS

Вся основная стилизация собрана в `app/static/css/styles.css`.

CSS отвечает за:

- сетки и layout;
- кнопки, формы, карточки;
- адаптивность;
- светлую и тёмную тему;
- оформление отдельных экранов.

### JavaScript

JavaScript в проекте используется точечно, а не как отдельный SPA-фреймворк.

Подход такой:

- основная страница генерируется на сервере;
- JS добавляет только интерактивность поверх HTML;
- это упрощает архитектуру и ускоряет разработку на хакатоне.

### SQLite

SQLite — это файловая база данных. Она хранится в `instance/hackathon.sqlite`.

Плюсы такого подхода:

- не нужен отдельный сервер БД;
- удобно для локальной разработки и демо;
- легко инициализировать через `init-db`.

### Werkzeug

Werkzeug используется Flask внутри и отдельно помогает с полезными вещами:

- `generate_password_hash` и `check_password_hash` для паролей;
- `secure_filename` для безопасных имён файлов.

### Matplotlib

Matplotlib нужен для страницы статистики: на сервере строятся графики, которые потом показываются на странице и могут выгружаться.

## Краткая схема потока

Обычно страница работает так:

1. Браузер отправляет запрос на URL.
2. Flask находит нужный route.
3. Route читает или изменяет данные в SQLite.
4. Python передаёт данные в Jinja-шаблон.
5. Шаблон превращается в готовый HTML.
6. Браузер применяет CSS и JavaScript.

Именно поэтому при добавлении нового раздела почти всегда нужно подумать о трёх уровнях сразу:

- route;
- template;
- database или client-side логика при необходимости.
